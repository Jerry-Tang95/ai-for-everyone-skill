# 《给所有人的AI入门课》共享术语词典 (glossary)

> **本词典由 v2.0 迁移产物（24 张能力卡）归纳，未回原课程逐讲核对。** 出处页码取自能力卡中已保留的讲课编号（pXX），未新增任何原文引用。
>
> **给 agent 的用法**：本词典是"作者原意"的锚点——同一个词在吴恩达的语境里常常有**特定的、可判断的**含义（例如"数据充足"不等于"有数据"、"任务"不等于"岗位"），下游能力卡若按字典义理解会给出相反建议。判断类问题先查本表，再决定调用哪张卡。

## 一、问题定义与项目判定类

| 术语 | 作者（吴恩达）的特定用法（不是字典定义） | 出处 |
|---|---|---|
| **A→B 映射** | 把业务问题形式化为"输入 A → 期望输出 B"的配对样本；它是 AI 项目的**立项书**——说不出 A 和 B，就没有项目可谈，也谈不上可行性 | p11 · p03 |
| **概念简单性** | 不是"看着简单"，而是"有经验的人能否在**一秒内**做出这个判断"的可操作代理；一秒打不住的就是复杂概念 | p06 |
| **数据充足性** | 不是"有数据"，而是"有没有足量的、**已标注的 (A, B) 样本**"；有数据 ≠ 数据够用，标注不一致等同于数据不足 | p06 |
| **一秒法则** | 人类一秒内能做的判断，当前（2019 监督学习）大概率可自动化；**只是初筛工具**，可行 ≠ 一定成功 | p06 |
| **双因素 2×2 矩阵** | 概念简单性 × 数据充足性 两个**独立且都必要**的维度，四象限各有行动建议：简单+有数据→立即推进；简单+缺数据→先补数据；复杂+有数据→谨慎推进；复杂+缺数据→放弃或重定义 | p06 · p07 |
| **ML 项目 vs DS 项目** | 唯一判据是**最终产出形态**——持续运行的软件（ML）还是一份决策建议/PPT（DS）；不是"哪个技术更高级"，而是流程、人才、成功指标都不同 | p04 · p11 · p12 |
| **任务 vs 岗位（自动化粒度）** | 岗位是多个任务的集合；可自动化的对象是"简单 + 有数据 + 高价值"的**单个任务**，不是整个岗位——所以"AI 取代 X 岗位"是错误的分析粒度 | p13 · p14 |
| **两个圆的交集（跨职能头脑风暴）** | AI 项目创意只长在"AI 能做什么"与"什么创造业务价值"的**交集**处；单独任一侧脑暴，产出的分别是"可行但无用"和"有用但不可行" | p14 · p24 |
| **三条价值路径** | 项目价值必须落到**降本 / 增收 / 新业务**之一（可多选，但要有主驱动力）；三问都答不上来，价值存疑，不该继续套算数字 | p15 |
| **技术尽职调查** | 用专家判断回答"系统能否达到预期性能、有无足够高质量标注数据、周期与关键技术风险是什么"——是项目可否启动的**技术门** | p15 · p06 |
| **三重尽职调查** | 技术 + 商业 + 伦理三项**独立并行且必须全过**；核心断言是"技术上能做、商业上该做"**不等于**"伦理上应该做" | p15 · p06 · p24 |

## 二、数据与工程类

| 术语 | 作者（吴恩达）的特定用法（不是字典定义） | 出处 |
|---|---|---|
| **统计化验收标准** | 验收写成"测试集达到 X% 准确率"，而不是"零错误"；并**提前**为那部分错误设计兜底（人工复核、降级流程） | p16 · p24 |
| **训练集 / 测试集** | 互不重叠的两个集合：测试集全程藏起来、**只在最终评估用一次**；用它调参等于泄露，报出来的数字就是虚高 | p16 |
| **数据飞轮** | "更好的产品→更多用户→更多数据→更好的产品"的自我强化循环；**成立前提**是产品改进直接依赖用户产生的数据——不是所有 AI 产品都有飞轮 | p16 · p18 |
| **数据护城河 / 不可复制的数据优势** | 真正难复制的不是算法（已被开源与云民主化），而是**独家、量大、持续更新**的数据；算法本身不是壁垒 | p19–p21 |
| **统一数据仓库 / 单一事实源** | 把散落各系统的数据汇聚到一个中央仓库并统一指标口径；作者称其为"AI 转型最重要的第一步"，但它是**长期工程**，要"边建边用" | p18 · p19 |
| **数据孤岛** | 数据**存在但拿不到**、各部门对同一指标有不同数字的状态；瓶颈是可访问性与口径，不一定是数据量 | p18 |
| **"足够好"数据** | 数据不必完美、达到预设门槛即可建模；门槛指"标注一致性达标 + 覆盖核心场景 + **无系统性偏差**" | p18 · p20 |
| **不为数据而收购** | 收购数据前先答"**谁用 / 做什么用 / 怎么变现**"三问；数据本身不等于价值，"先买下来再说"通常只是幻觉 | p03 |
| **误差累积 / 端到端准确率** | 串联模块的整体准确率≈各模块准确率**相乘**（0.95⁴≈81%）；单模块指标高 ≠ 系统整体好，要优先优化最弱环节 | p19 · p20 |
| **失败案例回流** | 部署后收集模型犯错的样本、加入训练数据重新训练——这是闭环的**燃料**，不是故障日志 | p11 · p16 |
| **AI 流水线** | 多个独立 A→B 模块依次处理数据的系统形态；关键约束是"必须有人对**端到端结果**负责" | p19 · p20 |
| **ML 项目闭环** | 收集 → 训练 → 部署 → 收集失败案例 → 再训练；是循环而非流水线，**第一次训练几乎必然失败** | p11 · p16 |
| **AI 项目生命周期** | 业务 + 技术融合的六阶段：定业务目标 → 数据准备 → 训练验证 → 部署 → 监控 → 迭代；数据准备常占时间大头，部署是迭代起点而非终点 | p08–p10 |

## 三、组织与落地类

| 术语 | 作者（吴恩达）的特定用法（不是字典定义） | 出处 |
|---|---|---|
| **AI 是新型电力（放大器）** | AI 是通用技术，它**放大**既有的数据、网络效应、品牌与规模，而**不凭空创造**优势——所以"用了 AI"本身不是优势 | p19–p21 · 另见入口核心命题 |
| **不在火车前冲刺（自建 vs 购买）** | 组件正在成为行业标准就购买采用，不要试图跑赢火车；只自建真正独特于业务、能带来差异化的部分 | p15 · p17 |
| **试点（pilot） / 先求成功再求价值** | 第一个项目选**最可能成功**而非最有价值的那个；用它积累信誉与组织信心，让飞轮转起来后再挑战高价值目标 | p22 |
| **AI 转型五步** | 试点积累势能 → 组建内部 AI 团队 → 全员分层培训 → 制定 AI 战略 → 统一内外沟通；**战略排在试点之后**，不是先写战略 | p05 · p22 |
| **分层 AI 培训** | 不同角色学不同深度：高管约 4 小时（学决策与评估）、经理约 12 小时（学管理 AI 项目）、工程师 100+ 小时（学构建） | p22 |
| **AI 团队角色** | 多学科组合：ML 工程师 / 数据工程师 / 产品经理 / 领域专家 / MLOps，**缺一不可**；只招算法工程师是最常见的失败配队 | p11–p13 |
| **T 型人才** | 在某一领域有深度、同时理解相邻领域的人；比"纯专才"更适配 AI 团队需要的共同语言 | p11–p13 |
| **AI 素养（AI literacy）** | 非技术人员的认知底线：知道 AI 能做什么、不能做什么、以及怎么评估一个 AI 项目——不是会写模型 | p22 |
| **迭代而非完美** | 定义"能上线的**最低**标准"，达到即发布、建反馈通道再持续迭代；完美不可达，真实用户反馈最珍贵 | p20 · p24 |
| **从小处着手 + 找伙伴** | 个人入门原则：第一个项目只要"**你能完成**"就够，找一个懂技术的伙伴，别等准备好——第二个项目会比第一个好 | p25 |
| **统一内外沟通（转型第五步）** | 确保员工、投资人、客户对公司 AI 方向有一致理解；信息不一致会直接损耗转型势能 | p05 · p22 |
| **"可见成功"的试点标准** | 试点的"成功"必须**事先**写成可见、可量化的指标（准确率达标 / 上线运行 / 业务指标改善）；否则项目做完仍会争执算不算成功，飞轮无法启动 | p22 |

## 附：易混词对照（agent 最常按字典义误读之处）

| 词 | 字典/常识义（**错误**用法） | 作者义（**正确**用法） |
|---|---|---|
| 数据充足 | 数据量大 | 有足量**已标注 (A, B) 样本**，且标注一致 |
| 数据有价值 | 数据能存下来、能卖钱 | 能转成明确的 **A→B 映射**并变现 |
| 简单任务 | 业务上不重要 / 技术不难 | **人类一秒内可完成判断** |
| 飞轮 | 增长快 / 用户多 | 产品改进**直接依赖**用户产生的数据 |
| 迭代 | 不断改版本 | 达到**预设门槛**就上线，靠**反馈数据**驱动下一轮 |
| 自动化岗位 | 用 AI 替掉这个人 | 拆成任务，只自动化**其中一个** |
| 护城河 | 技术领先 | **AI 放大的**数据 / 网络效应 / 品牌 / 规模 |
| 数据仓库 | 一个存数据的库 | **统一口径的单一事实源**，且要边建边用 |
| 100% 准确 | 高质量要求 | **不可能**，应改为统计化验收 + 错误兜底 |
